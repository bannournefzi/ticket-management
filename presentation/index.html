🏢 Tunisie Telecom — IT Department

Context & Problem Statement

⚠️ Before

  • IT support requests handled by email & phone
  • No centralised tracking — tickets were lost or forgotten
  • No visibility on response times or SLA compliance
  • Manual assignment leads to uneven workloads
  • No audit trail of changes or resolutions

✅ Goal

  • Build a full-stack web application to digitize ticket management
  • Provide role-based access for end users, analysts, and admins
  • Enforce SLA deadlines automatically
  • Offer dashboards and audit trails for full transparency
  • Innovate with AI-powered ticket creation and search

Objectives

👤 Métier Users

Submit IT support tickets, track their own requests, add comments and file attachments.

📊 Business Analysts

Triage, assign, and resolve tickets. Configure settings and monitor SLA compliance.

🛡️ Administrators

Manage users and roles. View platform-wide statistics and export reports.

⏱️ SLA Tracking

Automatic deadline calculation per priority. Real-time breach detection and alerts.

📈 Dashboards

KPI cards, Chart.js charts (status, priority, trends), and calendar views.

🔍 Audit Trails

Full history of every ticket change: who, what, when, old value → new value.

Architecture Overview

Ollama AI (llama3.2:3b) — port 11434
  • Stateless backend — JWT only, no server-side sessions
  • RoleGuard on Angular routes enforces access before API calls
  • HTTP Interceptor attaches Bearer token to every request automatically

User Roles & Access Control

RoleKey Capabilities
ROLE_METIER Create tickets · View own tickets · Add comments · Upload attachments
ROLE_BUSINESS_ANALYST View all tickets · Assign & change status · Internal notes · Configure settings & SLA
ROLE_ADMIN Full user management · View all tickets · Platform-wide stats · Export CSV

🔑 Roles are seeded automatically at startup via DataInitializer

📧 Registration uses OTP email activation before first login is allowed

🔒 Backend enforces permissions server-side via @PreAuthorize and custom JwtFilter

Core Feature: Ticket Lifecycle

NEW → ACKNOWLEDGED → CONFIRMED → ASSIGNED → RESOLVED → CLOSED
↕ any open state can transition to FEEDBACK and back

🔒 Server-side Validation

Each transition is verified in the backend — invalid transitions are rejected with a 400 error.

📜 Audit History

Every change logged: field name, old value, new value, actor, timestamp. Tamper-proof record.

👁️ Visibility Rules

Métier sees only their own tickets. BA and Admin see the full ticket table across all users.

  • Deadlines computed via @PrePersist based on ticket priority at creation time

  • Calendar view shows colour-coded events (red = breached, amber = at risk)

  • Configurable SLA hours in the Settings Panel

AI Features — Innovation Highlight

🎤 Voice-to-Ticket (AI)

Microphone→ Web Speech API→ Transcription→ Ollama llama3.2:3b→ Structured JSON→ Form Auto-fill

Fills: title · description · priority · category · tags. Confidence score displayed. Sanitized fallback on parse failure.

🤖 AI Chatbot — RAG (Retrieval-Augmented Generation)

User Question→ pgvector Search→ Relevant Tickets→ Ollama LLM→ Natural Language Answer

Tickets are indexed as vector embeddings in PostgreSQL (pgvector). The chatbot finds semantically similar tickets before generating its answer.

Challenges & Solutions

ChallengeSolution
Role-based access for 3 distinct user types JWT claims carry roles; Angular RoleGuard + backend @PreAuthorize checks
SLA breach detection in real time @PrePersist calculates deadlines; status computed at DTO level; calendar polling
AI voice input reliability Web Speech API + Ollama parsing with sanitized JSON fallback responses
Integrating external Mantis system REST client with configurable token/URL; manual push to avoid accidental sync
File storage without a dedicated file server Binary data stored as bytea in PostgreSQL for simplicity and atomicity
